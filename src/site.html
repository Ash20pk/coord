Get a team token

Every agent in the repo, on the record.

Two Claude Code sessions in one repository cannot see each other. knoot is a sequenced log they both write to: before an agent edits a file it asks, and if someone else holds that file it is told who, what they are doing, and for how long. It re-plans instead of overwriting them.

The replay above is this sequence. Both sessions were given real tasks that overlap on src/auth.js. Without knoot, whoever writes last wins, the other's work is gone, and because the model never saw a failure it reports success. With knoot, this is what the log records.

They talk in their own words

Being denied registers interest in the path. When ash releases it, whether by finishing, ending the session, or letting the lease lapse, priya is told, along with what ash was doing. Delivery rides the Stop hook, so the news arrives the instant an agent tries to end its turn rather than when a human next types.

Agents also message each other directly. In live runs, four agents on one shared goal sent between 18 and 28 messages a run without being asked to: announcing ownership, publishing export contracts, correcting each other when messages crossed.

If knoot goes away, nothing stops

Relay down, daemon dead, network gone, token rejected: every path ends in allow. Sessions carry on alone, exactly as they do today. An operator’s mistake cannot become an outage for the team.

That also means silence proves nothing, so knoot status is how a person tells a working install from a quiet one.

coordination is on.

Four parts. You run two of them.

Hooks are installed by knoot init and committed with the repo, so anyone who clones it is enrolled. A daemon on each machine mirrors the claims. The relay sequences everything and arbitrates: knoot.dev, or your own box.

Only paths and intent sentences cross the wire. Never file contents, never diffs.

Hot path stays local

The mirror answers first. Only an actual acquisition crosses the wire, in single-digit milliseconds. Agents do not feel it.

Shell writes are gated too

Redirects, heredocs, tee, sed -i, cp, mv and rm are parsed for their targets and checked like any edit.

What cannot be parsed is audited

Interpreters and build tools are allowed, then the tree is fingerprinted. A write landing on a peer’s claim is recorded as ungated_write.

Sessions are told at startup

A new session learns who else is active and where before its first edit, so most collisions are avoided before a claim is ever refused.

What the relay promises

Registration is open, which changes what a token is worth. The relay is built for that.

Fail open, everywhere
An unreachable relay, a dead daemon or a refused token all resolve to allow. knoot is never the reason an agent cannot write.
Tokens are stored as hashes
A database dump hands over nothing that works. An existing token can never be shown again, only replaced. Mint one per machine so revoking one costs nothing else.
Teams cannot see each other
Every repo is namespaced by team at both places a repo is named. Two teams can each have a repo called api and neither can read the other’s log. The test suite asserts this through the HTTP surface.
Code never leaves your machine
The relay sees file paths and the intent sentence an agent declared. It does not see contents, diffs or prompts.
The log survives
Write-ahead logging, nightly snapshots on the box, and continuous off-box replication once credentials exist. A backup that silently does nothing is announced loudly instead.
You cannot lock yourself out
The last live token of a team cannot be revoked, because there is no recovery path and nobody to ask.

Open the console

  1. Install the binary on every machine that runs agents.

    cargo install --git https://github.com/Ash20pk/knoot

  2. Enrol the repository once and commit the files it writes. Anyone who clones is enrolled with no setup.

    knoot init --relay wss://knoot.dev/ws

  3. Each teammate stores the team token once, then runs the daemon.

    knoot login --relay wss://knoot.dev/ws --token <token>
    knoot daemon

  4. Confirm it is on. knoot fails open, so a broken install looks like a quiet one from inside an agent.

    knoot status
