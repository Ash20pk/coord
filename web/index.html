Run ten coding agents on one repository without losing work.

knoot is a coordination layer for AI coding agents. Agents claim the files they are about to edit, hold them on a short lease, and hand any agent that wants a busy file the name of the holder and what they are doing. It works with any agent that can run a command before it writes.

Parallel agents are fast until two of them open the same file

One agent per repository is a solved problem. Four are not. They cannot see each other, so two will pick the same file, and the second write silently replaces the first. Nothing errors. The model that lost its work reports success, because from inside the session nothing failed.

Worktrees and branches move the collision to merge time rather than removing it. knoot removes it at the moment of the write, which is the only moment an agent can still change its mind.

Claim
The first write to a file takes it, on a ten-minute lease.
Lease
Renewed while the agent works, released when it stops, expired if it crashes.
Brief
Anyone else asking for that file is told who holds it and why, in the model's own context.
Log
Every claim, denial, write and message is one sequenced event stream per repository.

The refusal is written for a model, not for a log file

A plain error makes an agent retry. A brief that names the holder, their stated intent and the time left makes it do something else. That difference is the entire product.

Agent agnostic on purpose

knoot never talks to a model. It reads a small JSON payload on stdin and answers allow or deny on stdout, so anything that can run a command before it edits a file can be coordinated: a vendor's CLI, your own agent loop, a CI job, or a person with a shell alias.

Hook-based agents

Claude Code is wired up by knoot init, which writes the hook configuration into the repository. Any other agent with pre-tool hooks is the same three lines of config.

Anything with a shell

Call knoot hook yourself and read the exit status. The payload is documented, stable, and the same one the built-in integration uses.

Humans in the same repository

People collide with agents too. A shell function on $EDITOR puts a developer in the same log as the agents, holding leases the same way.

Your own runner

Agents that already have an orchestrator can call the relay's websocket directly and skip the daemon. The protocol is a handful of JSON messages.

Four parts, two of them yours

Hooks live in the repository and are committed, so anyone who clones it is already enrolled. A daemon on each machine answers the hot path locally. The relay sequences everything and arbitrates.

Only file paths and the intent sentence cross the wire. Never file contents, never diffs, never prompts.

Read the protocol

The hot path stays local

The daemon answers from a claim mirror in microseconds. Only an actual acquisition crosses the network.

Shell writes are gated too

Redirects, heredocs, tee, sed -i, cp, mv and rm are parsed for their targets and checked like any edit.

What cannot be parsed is audited

Interpreters and build tools run, then the tree is fingerprinted. A write landing on someone's claim is recorded as ungated_write.

Nothing can wedge the repository

Leases expire on their own. A crashed session releases its files without anyone intervening.

What the relay promises

The failure modes are the design. These are the ones that matter when you put it in front of a team.

It fails open, everywhere
Relay unreachable, daemon dead, token refused: every path ends in allow. knoot is never the reason an agent cannot write. Run knoot status to tell a working install from a quiet one.
Your code stays on your machine
The relay sees file paths and the intent sentence an agent declared. It does not see contents, diffs or prompts.
Agent tokens are stored as hashes
A database dump hands over nothing that works. Mint one token per machine so revoking one costs you nothing else.
Teams are isolated
Every repository is namespaced by team. Two teams can each have one called api and neither can read the other's log.
You can leave
The same binary runs the relay on your own box. The hosted service is a convenience, never a dependency, and the event log is plain SQLite.
